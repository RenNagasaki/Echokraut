================================================================================
ECHOKRAUT CHANGELOG
v0.19.3.3
================================================================================


==============================================================================
MAJOR NEW FEATURES
==============================================================================

[Voices] Optional: NPCs speak with their own game voice (EchokrauTTS)
  For NPCs that are voiced somewhere in the game, EchokrauTTS can now use their
  voiced lines from YOUR OWN FFXIV installation as the voice reference - the
  same NPC only, never a "similar" one. Off by default; the voice pack stays the
  default and is used for every NPC without a voiced line.

  - Settings -> Backend -> "Game voice reference". Switching it on shows a short
    notice you have to confirm. The recordings are decoded in memory only and
    never written to disk.
  - Only use it with your own, private EchokrauTTS instance - not with servers of
    other people or shared/public ones. Do not publish, stream, record or share
    what it generates.
  - "Build index" picks the best clips for every known NPC once; with "Rank the
    current NPC when a conversation starts" an NPC is also picked up on the fly.
    Until an NPC is indexed, the voice pack speaks - nothing waits.
  - Lines made with a game voice stay on your PC: they are left out of .ekpack
    exports and Google Drive uploads, and are marked "[Game voice]" in the Voice
    Clip Manager. Switching the feature off offers to delete them.
  - Needs EchokrauTTS with an engine that supports it (not AllTalk, not MOSS on
    PyTorch); otherwise the settings say so and the voice pack speaks.

[Voices] New EchokrauTTS engines: Qwen 0.6B and Qwen 1.7B
  Two new voice engines that come closest to the reference voices of all
  engines so far, with the first word heard after about a third of a second.

  - Settings -> Backend -> EchokrauTTS -> TTS engine: "Qwen 0.6B" (about 4 GB of
    free graphics memory next to the game) or "Qwen 1.7B" (sounds better, about
    5 GB).
  - Needs an NVIDIA graphics card; AMD with ROCm is experimental. Without a
    suitable card the install stops with a clear message instead of downloading.
  - Qwen keeps the graphics card busy while it speaks - if the game stutters,
    switch back to XTTS.
  - Two options below the engine list: "speaker embedding only" (needs no
    transcript, sounds less like the voice) and "calmer delivery".
  - Needs EchokrauTTS 0.0.2.0 and the local installer 1.3.2.0 (both are fetched
    on the next start / via "Check for updates").

[Voices] New EchokrauTTS engine: Pocket TTS
  A voice engine that runs on the processor, so the graphics card stays with
  the game - and it sounds clearly better than MOSS.

  - Settings -> Backend -> EchokrauTTS -> TTS engine: "Pocket TTS".
  - One model per language: German, French, Italian, Spanish, Portuguese and
    English. Japanese is not available.
  - "Pocket TTS: model size": 24 layers (default, better sound) or 6 layers
    (about twice as fast, sounds a little worse). German, Italian, Spanish and
    Portuguese have both; French only has 24 layers, English only 6.
  - "Pocket TTS: decoding steps": 4 is recommended; 1 is a little faster but
    can add an echo now and then (24 layers only), 8 is slower. Each model size
    remembers its own setting.
  - Needs EchokrauTTS 0.0.2.0 and the local installer 1.3.2.0.

[Voices] The engine list compares the engines
  Every entry in the EchokrauTTS engine list now says how good the engine sounds
  and what it needs, e.g. "Qwen 1.7B (Quality 5/5, GPU ~5 GB, high load)" or
  "Pocket TTS (Quality 3/5, CPU, 4 cores)". The list is sorted from best to
  simplest. The grades come from listening tests with German voices.

[Install] EchokrauTTS only installs the engine you use
  The local install used to download every engine and every model (about
  18 GB). It now installs only the selected engine (and for F5 only your
  language) - roughly 8 GB for one engine. Switching the engine downloads the
  new one on the next start, which takes a few minutes once. Models of engines
  you no longer use stay in <install folder>/echokrautts/models until you
  delete them yourself.

[Voices] Pick your own narrator voice
  Narration and system text (the lines nobody speaks) used to be locked to the
  voice shipped as "Narrator.wav". Any voice can be the narrator now.

  - Voices tab -> Configure on a voice -> "Use as narrator voice".
  - The voice acting as narrator is marked with "(Narrator)" in the voice list.
  - Untick it to go back to the shipped Narrator.wav. The same happens by itself
    if your chosen voice is switched off or disappears with a new voice pack -
    the narrator never falls silent.
  - Your pick takes effect on the next narrated line; already narrated lines keep
    their saved audio until it is deleted or regenerated.

[Voices] Regenerating always makes a new take
  Prepares for a coming EchokrauTTS version that answers an identical line
  requested again within a few minutes from a short-lived cache (and lets two
  requests for the same line share one generation). Lines generated from the
  Voice Clip Manager skip that cache, so "Generate"/"Regenerate" there always
  produces a fresh take.

==============================================================================
BUG FIXES
==============================================================================

[Install] Local EchokrauTTS install works on Linux
  On Linux (XIVLauncher) the local install and start failed within a split
  second. The installer runs inside Wine next to the game and could not start
  the wrapper as a native Linux program. It now does, follows its progress, and
  shuts the server down when you stop it or close the game. The legacy AllTalk
  install is not available on Linux and now says so instead of failing silently.

[Dialogue] Clicking in an Echokraut window no longer skips the dialogue
  Clicks in the Configuration, Game Data Tools, Voice Clip Manager and the two
  edit popups reached the dialogue box underneath and advanced it. The click test
  now follows the window at the HUD scale you actually play at, and covers the
  Configure-voice and Edit-character popups as well.

[Dialogue] The voice dropdown in the in-dialogue options keeps up with changes
  Voices you added or removed showed up only after a restart, and a voice you
  changed for the NPC in the Voice Clip Manager still read as the old one. The
  dropdown now follows both, and it always offers the voice the NPC is actually
  assigned - even one the race/gender filter would hide.

[Backend] Switching the engine shuts the old one down
  Switching between AllTalk and EchokrauTTS left the previous engine running, so
  it kept its model in graphics memory and still reported itself as running.

[Audio] No more garbled lines while the GPU generates
  When the engine produces audio slower than it plays (XTTS on a modest GPU),
  playback used to stutter its way through the line. Echokraut now measures the
  delivery rate and, for a source that slow, waits for the whole line and then
  plays it in one piece. Fast setups are unaffected and still start early.

[Install] XTTS install no longer fails with "A required privilege is not held"
  On Windows without Developer Mode, installing EchokrauTTS with the XTTS
  engine could stop while downloading the model (WinError 1314). The wrapper
  (EchokrauTTS 0.0.1.7) now downloads it without needing that privilege.

[Install] Starting the installer twice no longer breaks the install
  Starting the local install a second time while the first was still running
  could leave the EchokrauTTS folder locked for good ("Access is denied"). The
  newer run now takes over and cleans up what the older one left behind.

[Install] XTTS engine starts again after a fresh install
  With the current XTTS model download, the EchokrauTTS server stopped right
  at startup ("No such file or directory ... model.pth\config.json"). The
  wrapper (EchokrauTTS 0.0.1.8) now finds the downloaded model correctly.

[Backend] EchokrauTTS recovers by itself after a GPU error
  After a "CUDA error: device-side assert triggered" the local EchokrauTTS
  server kept running but failed every following line. It now shuts itself down
  and the installer starts it again (up to 3 times within 15 minutes); lines
  requested while it reloads its model are skipped. Needs EchokrauTTS 0.0.1.9
  (Settings -> Backend -> "Check for updates"); the updated local installer
  (1.3.1.0) is downloaded automatically on the next start.

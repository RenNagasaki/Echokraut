# DataClasses — TTS engine selection and per-engine config

Moved verbatim from `Echokraut/DataClasses/CLAUDE.md` on 2026-11-20 (file was over the 15k budget). Does not load by itself — read it before working in this area.

## TTS engine selection (EchokrauTTS feature — BLK-1)
- `Configuration.BackendSelection` (enum `TTSBackends.Alltalk | EchokrauTTS`) = which engine is active. **Default is `EchokrauTTS`** (fresh installs land on the recommended remote-ready engine → the First-Time engine selector highlights it by default). Because the field is new, existing installs would silently inherit this default and flip a working AllTalk setup; `MigrateBackendSelectionForExistingInstalls()` (run once from `Initialize`, gated on `Version < 1`) pins any config with `FirstTime == false` back to `Alltalk`, then sets `Version = 1`. Fresh installs (`FirstTime == true`) keep `EchokrauTTS`. After the one-shot bump the user's engine choice persists normally.
- Each engine carries its OWN mode + connection: `AlltalkData` and **`EchokrauTtsData`** (`EchokrauTtsData.cs`) each have `InstanceType`, `BaseUrl`, `LocalInstall`, `AutoStartLocalInstance`, per-engine `HasLiveGeneration`. Defaults: AllTalk `:7851`, EchokrauTTS `:8765`.
- **`EchokrauTtsData.TtsEngine`** (string, default **`"xtts"`**) = which sub-engine the LOCAL wrapper loads at startup, passed to the installer/wrapper as `--tts-backend` (normalized via `TtsBackendArg`). Only meaningful for Local (a Remote server's engine is fixed by its operator). `IEchokrauTtsInstanceService.SwitchTtsBackend(string)` **restarts** the running local instance; since wrapper **0.0.2.0** the bootstrap installs only the ACTIVE engine, so that restart downloads a not-yet-used engine first (no timeout on the ready wait, progress via NDJSON). **Deliberately a string, not an enum**: the engine list comes from the wrapper repo at runtime (see `TtsEngineCatalog` below), so the config must be able to hold an engine this plugin build has never heard of. The old enum field `TtsBackend` (`EchokrauTtsEngine?`) survives **only** as the migration source — `Configuration.MigrateTtsEngineId()` folds it into `TtsEngine` and nulls it, so it cannot run twice. Dropdown lives in the shared `NativeEchokrauTtsBuilder.BuildLocalInstance` → appears in both Backend tab + First-Time wizard. **Threading the arg requires the installer** (`EchokrautLocalInstaller` `echokrautts` mode, positional `args[7]`, → `--tts-backend`), so it needs an installer re-release to take effect.
- **`TtsEngineCatalog` / `TtsEngineInfo` / `TtsEngineOption`** (`TtsEngineCatalog.cs`) = the wrapper's published engine list (`engines.json` in the **Echokrautts** repo root: `id`, `name`, `minVersion`). Fetched by `ITtsEngineCatalogService` from `RemoteUrlsData.EchokrauTtsEnginesUrl` — a template whose `{version}` is replaced by `EchokrauTtsVersion`, so the list is read **at the release tag users can install**, with the default branch as second try and `Resources/Engines.json` embedded as the offline fallback. `Helper/Functional/TtsEngineAvailability` turns the catalog + `InstalledWrapperVersion` into the dropdown entries: die Version, gegen die geprueft wird, liefert `GatingVersion`: **installierter Tag bei bestehender Installation, sonst der Tag, den eine Neuinstallation holen wuerde** (`LatestWrapperVersion`) — „keine Installation" heisst NICHT „alles verfuegbar", sonst bietet der Ersteinrichtungs-Assistent eine Engine an, die das dort installierte Release gar nicht enthaelt. Eine Engine ueber der Gating-Version ist **gelistet, aber nicht waehlbar**, beschriftet `"NAME (from wrapper version X)"`; im Ersteinrichtungs-Assistenten (`listUnavailable: false`) wird sie ganz ausgeblendet — ausser sie ist die konfigurierte, die bleibt sichtbar UND gesperrt (sonst faengt der Selbsterhalt-Zweig sie als „verfuegbar" wieder ein). Das Dropdown zieht im Per-Frame-`Update` nach (`RefreshEngineOptions`, nur bei geaenderter Signatur und zugeklapptem Popup), weil die Nodes in `OnSetup` entstehen und ein Fenster-Neuoeffnen sie nicht neu baut. **`minVersion` gating is the one place wrapper tags are compared numerically** (`WrapperUpdatePolicy.IsAtLeast`); the update offer keeps its ordinal string compare. Anything unparseable on either side answers *available* — wrongly hiding a working engine is the more expensive mistake.
  - **Bewertung je Engine (2026-11-13):** optionale Felder `quality` (1–5), `hardware` (`gpu`/`cpu`), `vramGb`, `cores`, `load` (`low`/`medium`/`high`). `Helper/Functional/TtsEngineRating.Format` baut daraus das Label-Suffix `"(Quality 5/5, GPU ~5 GB, high load)"` (lokalisiert, nur ASCII-Zeichen: die Spielschrift hat keine sicheren Sterne/Punkte); `TtsEngineAvailability.Build(rating:)` hängt es hinter den Namen, VOR "(from wrapper version X)". Reihenfolge = Reihenfolge in `engines.json` (beste zuerst, Test `EmbeddedCatalog_RatesEveryEngine_BestFirst`). Schema bleibt `version: 1` — ältere Plugins ignorieren die neuen Felder.
  - **Sprachen je Engine (2026-11-26):** optionales Feld `languages` (Codes wie `--language`: `de`/`en`/`fr`/`ja`/…; leer = alle). Pocket: `de, en, es, fr, it, pt` — kein Japanisch. `TtsEngineAvailability.Build(language:)` sperrt eine Engine ohne Modell für die Client-Sprache (`IEchokrauTtsInstanceService.ClientLanguageCode`) mit `"NAME (not available in this game language)"`, `MinVersion` leer; das schlägt den Versionshinweis, weil kein Update das Modell bringt. Assistent blendet sie aus (außer konfiguriert → sichtbar + gesperrt). `ConfiguredEngineBlockedByLanguage` graut Install/Start aus, und `Launch` bricht davor ab (Status `LanguageBlockedFormat`, lokalisiert) — auch beim Start nach Login oder Engine-Wechsel, die nicht über den Button laufen. ⚠ Wirkt nur, wenn das `engines.json` am Wrapper-Tag das Feld trägt (der Remote-Katalog ersetzt das eingebettete); ältere Plugins ignorieren es.
- **`EchokrauTtsData.CustomModelUrl` / `CustomVoicesUrl`** (default `""`) = optional zip URLs (direct or Google Drive) for a user's own model + voice samples, analog to `AlltalkData.CustomModelUrl`/`CustomVoicesUrl`. Installed via `IEchokrauTtsInstanceService.InstallCustomData` → installer `installcustomdataek` mode → model into `echokrautts/models/echokraut_custom` (wrapper auto-detects it for the active engine), samples merged additively into `echokrautts/samples`. Needs the installer re-release. See `docs/claude/services/echokrautts-install.md`.
- **`EchokrauTtsData.InstalledWrapperVersion`** (string, default `""`) = git release tag of the wrapper currently extracted under `{TtsInstallRoot}\echokrautts`. Written by `IEchokrauTtsInstanceService` after a successful install/update from `RemoteUrlsData.EchokrauTtsVersion`; compared against that same remote value by `Helper/Functional/WrapperUpdatePolicy` to show the Backend-tab Update button + version label. Installs predating the handshake carry no value and are backfilled once by `MigrateWrapperVersionForExistingInstalls()` (run from `Initialize`) with `WrapperUpdatePolicy.AssumedLegacyVersion` = the single published wrapper release — otherwise they'd show "?" and be offered an update that re-downloads what they already run. **Do not bump that constant when a newer wrapper ships**: existing installs are then genuinely behind and must get the update (`WrapperVersionMigrationTests.AssumedLegacyVersion_MatchesTheWrapperReleaseWeShip` goes red at that point as the reminder to delete the assertion, not to raise the constant). The migration is gated on `LocalInstall` — Remote/None users keep the empty value. See `docs/claude/services/echokrautts-install.md` (wrapper update handshake) for the installer side.
- **`EchokrauTtsData.XttsFp16`** (bool, default **false**) = load the LOCAL XTTS model in half precision for ~1.3–1.8x faster inference. Passed as `--xtts-fp16 <true|false>` (via `XttsFp16Arg`, positional `args[8]`). Only has an effect with the XTTS engine on a CUDA/ROCm GPU (the wrapper's config field `xtts_fp16` gates it; ignored for F5 / CPU). UI is a checkbox in the shared local-instance builder, shown **only when a GPU is detected** (`IAlltalkInstanceService.IsCudaInstalled` — Windows always true, Linux `which nvcc`); the checkbox is omitted from `AllNodes` (not just hidden) when no CUDA so it reserves no layout slot. Applied via `IEchokrauTtsInstanceService.SetXttsFp16()` which persists + restarts the running local instance (shares `RestartLocalIfRunning` with `SwitchTtsBackend`). Also needs the installer re-release.
- **`EchokrauTtsData.QwenTemperature`** (double, default 0.9 = `DefaultQwenTemperature`, alternative `CalmQwenTemperature` 0.7) = Qwen-only wrapper option (engines `qwen-0.6b`/`qwen-1.7b`, wrapper 0.0.2.0), passed as `--qwen-temperature` via `QwenTemperatureArg` (**InvariantCulture** — a German client would send `0,7`), positional `args[9]` (custom-data mode `[11]`). The installer only forwards it when non-empty, so an older plugin keeps the wrapper default. UI: one checkbox beside the fp16 one (same CUDA condition, `GpuOptions` in `AllNodes`); setter `SetQwenTemperature` persists + `RestartLocalIfRunning`. **`QwenXvecOnly` („nur Sprecher-Embedding“) removed 2026-11-15** (user: only ever sounded less like the voice) — property, arg slot, checkbox, Loc key gone; an old config value is simply ignored on load; the wrapper keeps xvec only as its own fallback without a transcript. Defaults = user decision after a listening test (2026-11-12). Needs installer **1.3.2.0**.
- **Pocket-Optionen (`EchokrauTtsData`)**: `PocketLayers` (24 Default / 6, `--pocket-layers` via `PocketLayersArg`, Unbekanntes → 24, positional `args[11]`, Custom-Data `[13]`) und Schritte **getrennt je Größe**: `PocketDecodeSteps24` (1/4/8) und `PocketDecodeSteps6` (nur 4/8, `PocketStepOptionsFor(layers)`), beide Default 4. `PocketDecodeSteps` (nur lesen) = Wert der aktiven Größe, Unerlaubtes → 4; `TrySetPocketDecodeSteps` schreibt in den Slot der aktiven Größe und lehnt 1 bei 6 Layern ab. So zeigt ein Wechsel auf 6 bei gewählter 1 automatisch 4, und zurück auf 24 wieder 1 (User-Wunsch 2026-11-13). `--pocket-decode-steps` via `PocketDecodeStepsArg`, `args[10]` / `[12]`. UI: zwei Dropdowns (Größe, Schritte) nach den GPU-Optionen, **immer sichtbar** (CPU-Engine); Beschriftung aus `Helper/Functional/PocketOptionLabels` — die 1 steht bei 6 Layern mit „(24 layers only)“ da und wird abgelehnt (ein Dropdown kann keinen Eintrag ausgrauen). Setter `SetPocketLayers` / `SetPocketDecodeSteps` speichern + starten neu.
- **Engine-aware aggregates on `Configuration` — always gate runtime/UI on THESE, never `Alltalk.*`:**
  - `ActiveInstanceType` → the active engine's `InstanceType`.
  - `HasLiveGeneration` → `ActiveInstanceType != None`.
  - `StreamingGeneration` → shared "play as it streams in" toggle, honored by BOTH backends. Off = wait for the full clip before playback (AllTalk writes to disk first; `EchokrauTtsBackend.MaterializeAudioStream` buffers the response). `[JsonIgnore]` accessor backed by `Alltalk.StreamingGeneration` (no migration; the General-tab checkbox + both backends read this). EchokrauTTS previously ignored the setting and always streamed — fixed by routing both backends through this accessor.
- `TtsInstallRoot` = the shared install folder for BOTH engines (they live side by side under it). Migrated once from the legacy `Alltalk.LocalInstallPath` in `Initialize` (`MigrateTtsInstallRoot`). The Local install-path UI field binds to `TtsInstallRoot`.
- `InstalledInstallerVersion` = the `EchokrautLocalInstaller` release tag currently extracted on disk (BLK-5 version handshake; the provisioner re-downloads when it differs from the remote `InstallerVersion`).
- `EchokrauTtsResponses.cs` = DTOs for the EchokrauTTS `/tts` + health endpoints. `EchokrauTtsData.cs` also holds `HealthPath` (ready-probe path).
- Enum lives in `Enums/TTSBackends.cs`. The Backend-tab dropdown + First-Time engine selector both write `BackendSelection`.
